# 接口对接报告：视频转写产出 → 清洗项目接入规范

> **日期**: 2026-08-11
> **生产方**: 上游视频转写工具（ASR 音频转写 json + OCR 视觉文本）
> **加工方**: text-cleaning-engine（本仓库）
> **配套示例**: `示例文件/英文测试_示例.json` + `示例文件/英文测试_示例_visual.txt`
> **定位**: 数据格式契约 + 清洗边界 + 接口形态。清洗项目按此接入，无需猜测。

---

## 一、文档定位

上游转写工具产出两种文件，交给清洗项目加工后**回流给 Claude 生成笔记**。本文档让清洗项目**不加猜测地**知道：
1. 我们产出什么格式（每种文件 + 示例）
2. 每个字段什么意思（结构契约）
3. 哪些能洗、哪些**绝不能碰**（红线）
4. 清洗后返回什么格式（接口输出）
5. 将来作为工作流小模块怎么接入（srt 说明）

---

## 二、我们产出的两种文件（+ 示例）

### 文件 1 · 转写 json（ASR 音频转写）

**示例见** `示例文件/英文测试_示例.json`

```json
{
  "text": "全文拼接（英语转写 + 中文教学讲解混排）",
  "segments": [
    { "text": "段文本", "start_ms": 430, "end_ms": 8660, "confidence": 0.95, "review": false }
  ],
  "sentences": [
    { "text": "句文本", "start_ms": 430, "end_ms": 8660, "confidence": 0.95 }
  ]
}
```

### 结构契约（字段语义）

| 字段 | 含义 | 清洗时 |
|------|------|--------|
| `text` | 全文拼接（转写+讲解混排）| 只读参考，不单独洗 |
| `segments` | 语义段（约 1 句~几句），带时间戳 | **必须逐段清洗，保留字段** |
| `sentences` | 句（段内按标点切出），继承段时间戳 | **必须逐句清洗，保留字段** |
| `start_ms`/`end_ms` | 毫秒时间戳（定位视频用）| **绝不能改** |
| `confidence` | 启发式信心分 0~1（非真实 logprob）| **绝不能改值** |
| `review` | 低置信标记（confidence<0.5 为 true）| **保留**（Claude 靠它标[复核]）|

### 文件 2 · OCR+视觉 txt（画面文字 + GLM 描述）

**示例见** `示例文件/英文测试_示例_visual.txt`

```
===== 帧 00:00 (第1/179帧) =====
[画面文字 OCR]
坚持打卡30天听九口语突飞猛进   ← OCR 识别的画面文字
片名：查莉成长日记
[GLM画面理解]
画面是《查莉成长日记》片段的厨房餐桌场景...  ← GLM 视觉描述（有效内容）
```

- 每帧 = 帧标记 + OCR 文字块 + GLM 描述块
- 一个视频约 100-200 帧

## 三、清洗边界（红线清单）

### ✅ 能洗（清洗项目发挥处）

| 文件 | 能洗的内容 |
|------|-----------|
| visual.txt | 删 `===== 帧` 标记、`[画面文字 OCR]`/`[GLM画面理解]` 标签、独立成行的视频水印（坚持打卡/片名/知识点）、OCR 乱码碎片（dnrduork/MILK）|
| json | 标点乱码规范化（`,,`→`,`、`,.`→`.`、`??`→`?`）、连续标点压缩、**独立碎片**去重 |

### ❌ 绝不能碰（红线）

| 红线 | 原因 |
|------|------|
| **json 的 segments/sentences 结构不能拼平** | Claude 靠分句/分段生成笔记，拼平 = 废 |
| **中文讲解不能删** | 视频里中文是**教学讲解**（"一个人就说 listen"）是精华不是噪音 |
| **confidence/review/时间戳不改值** | 下游靠它们标[复核]、回看视频 |
| **srt 不清洗** | 见第五节 |

### ⚠️ 段级去重注意

json 里**同一个英语句子可能重复出现**（视频反复放），但**中间夹着中文讲解**：
```
段1: "Okay, everybody, listen up..." (英语)
段2: "想让别人认真听...listen up 口语" (中文讲解)
段3: "Okay, everybody, listen up..." (英语又来了)
```
**去重必须"文本相似 + 时间区间不重叠"**（时间戳锚定），且**别删带中文讲解的重复**——它是有意的重播，不是噪音。

## 四、接口形态（清洗后返回什么）

**方案（已确认）**：清洗后仍保 json 结构，生成新文件，不覆盖原文件。

| 项 | 决定 |
|----|------|
| 输出格式 | **保 json 结构**（逐段/逐句清洗后的 segments/sentences + 保留字段）|
| 输出文件 | **生成 `_clean` 新文件**（如 `英文测试_clean.json`），原 json 保留 |
| 原文件 | 保留（溯源用，学生对比原视频）|
| 消费方 | 清洗后的 `_clean.json` 喂给 Claude 生成笔记 |

### 为什么保结构不拼平
此前的重构计划指出缺点#1："ASR 结构化丢失——segments 在入口被拼平"。Claude 读**分句/分段 + 时间戳**的 json，比读一长段**更准**（能对齐"这句在说什么"）。

---

## 五、srt 说明（将来模块接入位置）

**srt 不清洗**——保留时间戳/序号，是"给人看"的字幕文件。

**关键认知**：清洗项目将来是**嵌入 上游转写工具 工作流的一个小模块**，不是一次性外部工具。接入位置：

```
提音频 → 转写 → 生成 json + visual.txt + srt
                      │
                      ▼
              [清洗模块插这里]  ← 将来清洗项目作为模块接入
                      │
                      ▼
            清洗后的 _clean.json + _clean_visual.txt
                      │
                      ▼
              喂 Claude 生成笔记
```

- srt 由 json 导出（现有 `export_srt`），**不经清洗**——它是独立产物
- 若未来需要"带时间定位的转写"，另议

## 八、GLM 描述内嵌界面词的提示词约定（方案 D 定案 2026-08-11）

**背景**：真实 179 帧数据实测，GLM 描述里固定界面词大量重复（`坚持打卡30天` 出现在 93% 帧、`片名` 71%、`知识点` 86%），占描述字符约 13%。

**定案**：**不清洗层剔除**（正则删词会误伤紧邻的台词/单词卡/例句，见风险分析），改为 **上游转写工具 笔记阶段提示词忽略**。

**上游转写工具 生成笔记时，请在提示词中加入以下说明**：

```
【界面固定文字说明】
视频画面中的这些文字是固定学习界面，不是教学内容，请忽略：
- 顶部：坚持打卡30天 听力口语突飞猛进 / 片名：查莉成长日记
- 底部：高手盲听 / 纯英文字幕 / 初学看字幕 / 知识点12345 678 91011121314 等
- 其他每帧固定出现的 UI 词（点赞/收藏/关注/爱说英语的福安 等答主水印）

请聚焦真正的教学内容：
- 英语台词（如 "Now that we have the new baby"）
- 单词卡/音标/释义（如 stellar /ˈstələr/ adj.一流的）
- 中文讲解/翻译
- 人物动作与场景变化
```

**注意**（该提示词的局限）：
- 只让 Claude 忽略，**不省 token**（界面词仍占上下文窗口）
- 1 小时长视频（上千帧）时界面词重复可能挤占上下文，届时建议 上游转写工具 侧做"描述级句式压缩"或分块喂入
