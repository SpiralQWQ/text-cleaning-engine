## 〇、接口契约（上游转写工具 转写产出 → 清洗项目接入规范）

> **来源**: `docs/接口对接/接口对接报告.md` + 示例文件。这是清洗项目的**输入格式契约 + 输出接口 + 红线**，所有补丁必须遵守。

### 输入：两种文件

| 文件 | 结构 | 关键字段 |
|------|------|---------|
| `xxx.json` | `text`(全文) + `segments[]`(语义段) + `sentences[]`(句) | 段/句含 `text/start_ms/end_ms/confidence`；segments 还含 `review` |
| `xxx_visual.txt` | 帧标记 + `[画面文字OCR]`块 + `[GLM画面理解]`块 | 每帧 100-200 帧 |

### 字段契约（清洗时）

| 字段 | 含义 | 清洗时动作 |
|------|------|-----------|
| `text` | 全文拼接（转写+讲解混排） | 只读参考，不单独洗 |
| `segments` | 语义段（约1句~几句），带时间戳 | **必须逐段清洗，保留字段** |
| `sentences` | 句（段内按标点切出），继承段时间戳 | **必须逐句清洗，保留字段** |
| `start_ms`/`end_ms` | 毫秒时间戳 | **绝不能改** |
| `confidence` | 启发式信心分 0~1 | **绝不能改值** |
| `review` | 低置信标记（confidence<0.5 为 true） | **保留**（Claude 靠它标[复核]） |

### 输出接口（已确认）

- 清洗后**保 json 结构**，生成 **`_clean.json` 新文件**（如 `英文测试_clean.json`），原 json 保留（溯源）
- `_clean_visual.txt` 同理
- 清洗后的文件喂给 Claude 生成笔记

### 红线清单（绝不能碰）

1. **segments/sentences 结构不能拼平**——Claude 靠分句/分段生成笔记
2. **中文讲解不能删**——视频里中文是教学讲解（"一个人就说 listen"），是精华不是噪音
3. **confidence/review/时间戳不改值**——下游靠它们标[复核]、回看视频
4. **srt 不清洗**——保留时间戳/序号，给人看

### ⚠️ 段级去重的特殊要求

json 里同一英语句可能重复（视频反复放），但**中间夹着中文讲解**：
```
段1: "Okay, everybody, listen up..." (英语)
段2: "想让别人认真听...listen up 口语" (中文讲解)  ← 不能删
段3: "Okay, everybody, listen up..." (英语又来了)
```
**去重必须"文本相似 + 时间区间不重叠"（时间戳锚定）**，且**别删带中文讲解的重复**——它是有意的重播，不是噪音。

### 接口带来的新要求（对原补丁计划的调整）

| 原计划 | 接口调整 |
|--------|---------|
| R1 输出"按段拼接文本" | **升级**：输出保 json 结构 `_clean.json`（逐段/逐句清洗后的 segments/sentences + 保留字段），不止分段文本 |
| F2 去重"相似度+时间戳" | **强化**：时间戳不重叠是**硬判据**（接口红线：同文本+同时间=重复记录；同文本+不同时间=重播），且**中文讲解段永不删** |
| 问题4 词级纠错 | **定位调整**：`S tla r`→stellar 由 **Claude 生成笔记时纠正**（接口开放问题 #3 确认），清洗层只做安全的标点/碎片处理 |
| 问题3 OCR碎片 | **新要求**：`Dishuching`/`MILK`/`语的` 这类单次碎片需删，但**现有 ≥3 次高频规则漏删短样本**（示例只有 4 帧，独立行 2 次 < 阈值） |

### ✅ 接口开放问题定案（用户确认 2026-08-11）

#### Q1: `_clean.json` 逐段映射 or 合并/拆分段 → **逐段映射（A）**

- 清洗后**段数量、时间戳、边界、review 与原文一一对应**，只改每段 text
- **空段处理**：某段原本是纯噪音（如整段水印）→ 清洗后 text 留空，**段保留、时间戳/review 保留**，Claude 读 json 见空段自然跳过
- **正文段不会空**（中文讲解/英语教学/GLM 描述是正文，规则保守不删）
- 短段（如 `S tla r` 5 字）不视为空，保留（review=true 标记，Claude 复核）
- **红线遵守**：时间戳/review 不改，段边界不动

#### Q2: GLM 描述内嵌水印 → **保留不剔除（B）**

- 独立成行的水印（每帧重复）由独立行规则删；**描述句子里嵌的水印是 GLM 对画面的客观描述**，保留
- 粗暴抠词会破坏句子结构，风险 > 收益
- **长视频边界**（用户确认）：1 小时视频几百帧描述，由 **上游转写工具 笔记生成阶段**做结构化分块/模块化喂 Claude（参考 AudioNotes Map-Reduce 6000 字符切块），**清洗层不管长视频分块**——只保证 `_clean_visual.txt` 干净、每帧结构清晰、可被下游按帧/时间窗口切分，不拼接所有帧

#### Q3: 词级错误谁纠正 → **Claude 笔记阶段纠正（B）**

- `S tla r`→stellar 等词级错误由 **Claude 生成笔记时凭上下文纠正**（接口开放问题 #3 已确认）
- 清洗层**只做安全处理**：词内空格重接（`S tla r` 段内字间空格合并）、标点规范化（`??`→`?`）
- **不做**语义级改词（词典/编辑距离），避免把正确的专名/术语改错
- `review=true` 段保留，Claude 靠它标[复核]

### 1.1 致命缺点（阻塞性）

| # | 缺点 | 代码依据 | 影响 |
|---|------|---------|------|

## 三、有必要重构的内容（含确认点）

> 这些仓库技术栈/架构特别好，但与我们的轻量规则引擎定位有冲突。**逐项确认是否值得重构**。

### R1. `clean_text` 字符串签名 → 段列表签名（保 json 结构输出）⚠️ 需确认

**冲突**：现状 `clean_text(raw: str) -> str` 单字符串进出。问题1/2/3 的所有补丁（逐段清洗/段级去重/块级判定）都要求**段列表进、段列表出**。8+ 份报告（PaddleOCR/MinerU/Umi-OCR/gnehs/VideoCaptioner/AsrTools）共同判定先拼平再清洗是"根本性错误方向"。**接口契约强制要求**：输出保 json 结构 `_clean.json`，逐段/逐句清洗后 segments/sentences + 保留时间戳/confidence/review。

**重构理由**：不改架构则问题1 无解，且**直接违反接口红线**（Claude 靠分句生成笔记）。所有 400 仓库里没有一家是"先拼长串再逐段恢复"的成功做法。

**融入建议（一次重构，不引框架）**：
- 新增 `cleaner/block_pipeline.py` 作为 ASR/OCR 形态入口：`clean_blocks(blocks: list[Block]) -> list[Block]`，Block = `{text, start_ms, end_ms, confidence, review}`
- 新增 `cleaner/asr_parser.py`：`parse_asr(json) -> {segments: [Block], sentences: [Block]}`（多引擎异构收敛）
- 新增输出形态：清洗后生成 `_clean.json`（保 segments/sentences 结构 + 保留字段），原 json 保留
- `clean_text` 保留给 HTML/纯文本形态（不破坏现有 40 篇知乎 + 视频清洗）
- 规则层逐块应用，**时间戳/confidence/review 字段透传不改**；末尾按需组装为 `_clean.json`
- 工作量 ~150-250 行，零新依赖

**接口落地形态**：
```
输入 xxx.json → asr_parser 解析 → 逐段/逐句清洗(text 只改标点/碎片/去重)
    → 输出 xxx_clean.json（segments/sentences 保留 + 字段不变）
输入 xxx_visual.txt → 逐帧清洗(删帧标记/水印/OCR碎片/GLM标签)
    → 输出 xxx_clean_visual.txt（GLM 描述保留）
```

### R2. 规则 YAML 从"删行规则"升级为"多动作规则引擎" ⚠️ 需确认

**冲突**：现在 `noise_substr`(子串删行)/`noise_regex`(正则删行) 两类动作。需新增 `protect`(保护)/`replace`(查表替换)/`dedup`(判重)/`classify`(打标)/`accept`(放行) 五类动作；并补 `video_asr` 分组 + `typo_fix`/`lexicon`/`dedup.*`/`line_classifier` 等区块。

**重构理由**：问题4 的纠错表、问题3 的碎片打标、问题2 的去重参数都需要"非删行"动作承载；继续用子串删行塞不下。

**融入建议**：
- 保持 YAML 数据化哲学（加配置不改代码），只是规则 schema 扩展
- `_RULES_SCHEMA` 同步扩展（jsonschema 已有），新增区块不破坏现有
- 工作量 ~50-100 行 schema + 引擎分发逻辑

### R3. 去重位置：文件级后置 → 段落级内联（时间戳锚定 + 中文讲解保护）⚠️ 需确认

**冲突**：`_dedup_check` 在清洗输出后做文件级查重（报告用）；问题2 的重复发生在**文档内部段落**，需在清洗管线内（归一化后、校验前）做段级去重。

**重构理由**：文件级 md5 无法处理"单文档内重复段"；视频反复播的场景发生在段落层面。**接口红线强制**：去重必须"文本相似 + 时间区间不重叠"（时间戳锚定），且**别删带中文讲解的重复**。

**融入建议**：**两者并存**——段级去重内联进管线（删重复段），文件级查重保留作报告。段级是主，文件级是辅。

**去重判据（结合接口示例实测）**：
| 情况 | 判据 | 动作 |
|------|------|------|
| 同文本 + **同时间戳**（如示例 seg[2]/seg[5]） | 数据重复记录 | 删后留前 |
| 同文本 + **不同时间戳**（视频重播，中间夹中文讲解） | 有意重播 | **保留**（接口红线：中文讲解不删） |
| 带中文的段重复 | 教学重播 | **永不删** |
| 整行精确重复 ≥3 次（水印） | 视频水印 | 删（现有规则保留） |

### R4. clean-text 参数按 form 分叉 ⚠️ 需确认

**冲突**：全局 `fix_unicode=False` 为中文排版；英文 ASR 需要开 True（ftfy 修 mojibake）。

**重构理由**：单一路径无法同时服务中英；`S tla r` 类错误部分是编码/转义问题。

**融入建议**：`normalize_stage1(text, form)` 加 form 分支，`form in ("video_asr",)` 开英文路径 + `exceptions` 保护。

### R5. 校验层 → "校验+修复重试" + 可选 LLM 层 ⚠️ 需确认

**冲突**：`validate_schema` 只报错不改；LLM 纠错 stage 需要"校验+反馈+重试≤3轮"循环。

**重构理由**：词级纠错到规则极限（OOV/语义错误）需 LLM 兜底；LLM 输出质量不可保证，必须有校验重试闭环。

**融入建议**：`cleaner/llm_correction.py` 可选 stage（默认关，仅 ASR/OCR 源，低置信才触发，走现有 GLM 桥接，diskcache 缓存，token 预算上限）；规则路径保持确定性。

### R6. 输出层 Formatter 多态 ⚠️ 低风险

**冲突**：输出散落 .txt，无统一出口。

**融入建议**：`cleaner/formatters.py` 基类（txt/md/srt），为将来带时间戳输出铺路。低风险，可与 R1 一起做。

### R7. 规则指纹路径 bug 修复（F3）—— **必须做，无需确认**

`clean_batch.py:69` `config` → `rules`。一行修复，恢复增量失效机制。

## 五、结论

400 仓库调研 + 接口契约给出了**高度共识的技术路径**：清洗层"消费结构、逐段处理、保 json 结构输出 `_clean.json`"是问题1 的正解（零新依赖、接口强制）；问题2 去重需"时间戳锚定 + 中文讲解保护"（接口红线）；问题4 词级错误由 Claude 笔记阶段兜底（接口开放问题 #3 确认），清洗层只做安全碎片/标点处理；问题3 需多信号综合（依赖确认帧 OCR 是否保留 box）+ 补短样本水印规则（F4）。

**关键调整（接口带来的）**：
1. **输出形态**：从"分段文本"升级为"保 json 结构 `_clean.json`"（R1 核心）
2. **去重红线**：时间戳不重叠是硬判据，中文讲解段永不删（R3 强化）
3. **词级纠错降级**：Claude 兜底，清洗层不强行纠错（问题4 定位调整）
4. **短样本水印**：需补 YAML 规则（F4，接口示例实测暴露）

**8 个重构点里 6 个需要你确认**（R1-R6），1 个必须做（R7/F3 bug），1 个新发现（F4 补规则）。建议按阶段推进：先 P0 接口适配（修 bug + 补水印 + 原型验证），再 P1 结构化重构，P2 去重/碎片，最后 P3 深化。

> 详细单仓库方案见《高分仓库补丁建议汇总.md》与 4 份分类分析（`docs/调研/_analysis/`）。
