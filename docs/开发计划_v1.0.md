## 二、数据清洗大佬的"规范"参考（扫描调研仓库提取）

### 2.1 清洗规范（设计原则）

| 规范 | 说明 | 对应仓库 | 我们状态 |
|------|------|---------|---------|
| **单一入口** | 一个 `clean()` 函数 + 开关控制，易调试 | clean-text | ✅ clean_text 主入口 |
| **模块化 cleaners** | 20+ 纯函数单调，可组合 | unstructured | ✅ clean_* 函数家族 |
| **管道组合** | 预处理步骤可组合（custom_pipeline） | texthero | ✅ Stage0-5 管道 |
| **专用函数家族** | clean_text/clean_url 按数据类型分治 | dataprep | ✅ clean_* 命名 |
| **动词链式** | filter/sort/uniq 链式流水，每段可预览 | miller | ⚠️ 管道已有，可预览增强 |

### 2.2 工程完善（还没做的）

| 完善 | 说明 | 借鉴 | 价值 |
|------|------|------|------|
| **并行批量清洗** | 多进程加速大批量 | clean-text 的 `clean_texts()` | 🔴 高——大批量语料时快 N 倍 |
| **清洗后去重** | 内容哈希/相似度，去近似重复文本 | dupeguru 内容哈希 | 🟡 中——数据多了防重复 |
| **质量断言扩展** | ge/lt/isin/正则/自定义断言 | pandera Check / GE | 🟡 中——更多质量门槛 |
| **管道编排/重试** | 清洗步骤失败重试/监控 | prefect 思想（轻量自研） | 🟢 低——可选 |
| **调试预览** | 每阶段输出可预览 | miller `mlr cat` | 🟢 低——CLI 已可预览 |
