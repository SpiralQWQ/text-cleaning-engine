## 二、核心发现：A-E 问题的 GitHub 方案

### 问题 A · 台词重复误删 → **时域相似度去重 + 压缩保留** 🔴

**根因确认**：我们的"整行重复≥3次删"用**全局计数**，把教学台词（视频反复播放）当水印误删。GitHub 共识：

| 方案 | 来源仓库 | 核心思路 |
|------|---------|---------|
| **时域相似度去重** | YaoFANGUK `_remove_duplicate_subtitle` | 维护时间/顺序连续窗口，相邻行做 **Levenshtein 相似度**（阈值 0.8，空白归一化），相似归并为一个"台词事件"，取最长代表 |
| **重复压缩保留** | gnehs `compactRepetitiveSubtitleText` | 相同台词合并后输出 `原文…[出现36次]`——**保教学强调信号 + 省 token**，不删除 |
| **句级去重粒度** | wikimedia/sentencex | 先归一化句子（拆行已合并）再判重复，粒度从"整行"升到"句子" |
| **源头抑制** | whisper.cpp/faster-whisper | `repetition_penalty`/`no_repeat_ngram_size`/`hallucination_silence_threshold` 降 ASR 幻觉型重复 |

**落地**：删掉"全局计数≥3次删"，换"时间窗口内相邻行相似度归并 → 压缩标注 [出现N次]"。

### 问题 B · 界面水印 → **坐标+内容双轨检测** 🟡

**根因确认**：水印（`坚持打卡30天`×174）每帧固定位置重复，但和台词同样重复，难区分。

| 方案 | 来源仓库 | 核心思路 |
|------|---------|---------|
| **坐标归一化+频次统计** | YaoFANGUK `_detect_watermark_area` | 坐标并查集归一 → Counter 频次 → **固定坐标出现次数远超台词中位数的区域判水印区** → 删该区（3星，但需上游保留坐标） |
| **内容启发式** | 纯文本降级 | 命中"打卡\|片名\|第\d+集\|关注\|点赞\|订阅"等 UI 特征词，且次数>阈值（≥30次）→ 删 |
| **多层词表架构** | sentencex/gnehs | 水印词表（B）/教学词表（A/E）/乱码启发式（C）三张表分离 |

**落地**：纯文本时用"UI 特征词 + 高频"启发式；若 media-to-notes 保留帧坐标则用坐标双轨。

### 问题 C · OCR 乱码 → **乱码四重门** 🟡

**根因确认**：`dnrduork`/`Chury` 无意义碎片与教学短行长得一样。

| 方案 | 来源仓库 | 核心思路 |
|------|---------|---------|
| **词典校验** | YaoFANGUK | wordsegment 判断"整行是否由真实英文单词构成"，非词占比高 → 判乱码；中文用常用字覆盖率 |
| **信息熵/字符分布** | 启发式 | 大量重复字母、无元音串（`dnrduork`）、符号密集 → 判乱码 |
| **置信度门槛** | VSE | 上游若带 score，<阈值直接弃 |
| **typoMap 兜底** | YaoFANGUK | 已知错字替换表（`l'm→I'm`），保留删除表 |

### 问题 D · OCR 拆行 → **句子归一化 + 续句合并** 🟡

**根因确认**：`Okay, everybody. Listen` + `up.` 一句被断成两行。

| 方案 | 来源仓库 | 核心思路 |
|------|---------|---------|
| **sentencex 前置切句** | wikimedia/sentencex（3星） | `pip install sentencex`，`get_sentence_boundaries("zh/en")` 把跨行断开的台词合并为完整句子；`is_paragraph_break` 区分"台词断行"vs"真实换行" |
| **续句启发式** | gnehs | 上一行无终止标点 + 下一行小写开头 → 拼接 |
| **多边界切分** | sentsplit/syntok | 句号接小写=非真句尾判据 |

### 问题 E · 教学短行 → **教学词表保护** ✅

**根因确认**：`Listen up.`/单词卡/音标/中文翻译是教学精华，乱码判别不能误伤。

| 方案 | 来源仓库 | 核心思路 |
|------|---------|---------|
| **教学词表** | sentencex/gnehs | `Listen up`/`Now that` 等强调短语命中即保并压缩 |
| **LLM 预分析保护清单** | gnehs `analyzeSubtitlesForContext` | 清洗前 LLM 采样产出"教学关键词/重复强调短语保护清单"，作 allowlist（失败静默降级） |
| **确定性规则** | 自研 | 音标（`/.../`）/单词卡（`n.释义`）/中文翻译结构 → 保护 |

## 六、结论

**400 仓库调研确认**：A-E 问题都有成熟可移植的 GitHub 方案，核心是——
1. **A 台词**：把"全局计数删"换成"时域相似度去重 + 压缩保留 [出现N次]"（YaoFANGUK + gnehs）
2. **B 水印**：UI 特征词 + 高频启发式（纯文本降级）或坐标双轨（有坐标）
3. **C 乱码**：词典校验 + 信息熵四重门
4. **D 拆行**：sentencex 句子归一化 + 续句合并
5. **E 教学**：教学词表/音标/单词卡结构保护

**最优先**：阶段 1（纯规则零依赖）——删错规则、改对台词保留、补水印/乱码/续句规则，用真实数据验证。

> **实现需用户确认后才动手**。详细单仓库方案见 400 份报告 + 本目录 `报告/` 下各 `补丁建议` 段。
