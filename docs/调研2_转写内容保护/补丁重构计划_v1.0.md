## 〇、核心病灶定位（代码实证）

**A 问题的唯一元凶**在 `cleaner/cleaning.py`：
```python
# 第303-304行: 全局计数, 不看时间/语义
high_freq = {l for l, n in Counter(lines).items() if n >= 3}
# 第336-337行: 命中即删
if l in high_freq and l not in _KEEP_HEADINGS: continue
```
**它把教学台词（视频反复播放×36）和中文翻译（×26）当水印误删了。**

**好消息**：`cleaner/clean_asr_json.py` 的 `_dedup_segments()` 方向是对的（同文本+同时间=重复删、同文本+不同时间=重播保留、中文段不删）——可作改造基准，但缺「压缩标注 [出现N次]」和「教学/水印分类」。

## 一、本项目缺点（对照 400 仓库暴露）

### 1.1 致命缺点
| # | 缺点 | 证据 |
|---|------|------|
| **F1** | **"整行重复≥3次删"全局计数一刀切**，误删台词/翻译 | 6+ 仓库点名反模式（yottaawesome/manasnilarout/mformigo） |
| **F2** | **无"压缩保留"通道**——只会删，不会输出 `原文…[出现36次]` | gnehs/SubtitleEdit/VideoLingo 都有现成格式 |
| **F3** | **教学/噪音无分类层**——一条规则同时管"台词(保)""水印(删)" | SeanWong17 教训：检测重复≠知道该保该删 |

### 1.2 显著缺点
| # | 缺点 | 证据 |
|---|------|------|
| **S1** | 无乱码检测（`dnrduork`/`Chury` 未处理） | SubtitleEdit OcrFixEngine 可移植 |
| **S2** | 无拆行合并（`Listen`+`up.` 不拼） | sentencex/SubtitleEdit/ffsubsync 三份直接命中的解 |
| **S3** | 无时间戳维度（区分不了"36次教学"vs"174次水印"） | mformigo 核心教训 |
| **S4** | 无审计（删了什么、为什么不可追溯） | BufferFis edits+why |
| **S5** | 无质量门禁（只有 14 项验收，无"教学保留率"量化） | balance-joe failure_count==0 |
| **S6** | 处理粒度是"行"不是"句"（拆行碎片被当独立行） | neurosnap/sentencex 一致 |
| **S7** | 规则全是"删"类动作，无保/压缩/合并 | 我们 YAML 缺动作类型 |

## 二、可吸取内容（分四类）

### A. 可直接打补丁的（针对 A-E）

#### 治 A 台词重复 → 时域归并 + 压缩保留（三家合流）
| 来源 | 算法 | 落地 |
|------|------|------|
| **YaoFANGUK** | `_remove_duplicate_subtitle`：时间窗口相邻行 Levenshtein ≥0.8 归并 | 改 cleaning.py 高频块 |
| **gnehs** | `compactRepetitiveSubtitleText`（MIT）：`预览3次…[repeats N times]` | 移植 `compact_repetition()` |
| **SubtitleEdit** | `MergeLinesSameTextUtils`：连续相同行合并+时间轴覆盖 | 只在连续相邻时合并 |

#### 治 B 界面水印 → 时间戳判据分水岭
| 来源 | 算法 |
|------|------|
| **jdepoix/youtube-transcript-api** | **同文本≥3次，间隔基本恒定→教学强调(压缩保留)；间隔≈0(同帧)→水印(删)** ← 我们 json 已有 start_ms，直接可用 |
| **YaoFANGUK** | 坐标双轨（有坐标）/ UI特征词+次数>30（纯文本降级） |

#### 治 C OCR乱码 → 四层漏斗（先保教学再删乱码）
| 层 | 方法 | 来源 |
|----|------|------|
| 0 | 教学白名单前置（音标/翻译/单词卡）→ 跳过 | SubtitleEdit/spellux |
| 1 | 字符级：无元音/连续辅音簇/纯符号 | hide3tu/noc-lab |
| 2 | 词典命中率：OOV≥50% 判乱码 | SubtitleEdit OcrFixEngine |
| 3 | 置信度：conf<0.3+词典外才删 | PaddleOCR |
| 4 | 分级裁决：AUTO-DELETE/NEED-JUDGE/AUTO-KEEP | hide3tu |

#### 治 D OCR拆行 → 三判据合并
| 来源 | 判据 |
|------|------|
| **adrianmusante** | 上行无句末标点 + 下行小写/`&`/`,`开头 + 时间相邻 → 合并 |
| **sentencex** | `get_sentence_boundaries("zh/en")` 句子归一化，非破坏性 |
| **SubtitleEdit** | `MergeShortLinesUtils` 阈值化合并 |

#### 治 E 教学短行 → 教学白名单
| 来源 | 方法 |
|------|------|
| **12+ 报告共识** | 音标行/中文翻译行/单词卡行/祈使短句 → PROTECTED，放所有删除前 |

### B. 可融入方法（算法/架构/工程模式）
- **两遍式「先计数再分桶」**（qr4d/hecor）：第一遍 Counter 统计 + 第二遍按教学/水印/乱码分桶
- **检测≠决策分离**（hecor/SeanWong17）：重复检测器当子模块，上层叠分类层
- **skip_filtering 只标记不删**（leeroopedia）：台词压缩保留的先决架构
- **false-positive 精确复验**（leeroopedia）：粗聚簇→精确Jaccard复核→再决策
- **低置信度标记代替删除**（ChatPRD）：`[garbled]` 不猜词
- **LLM 分批逐行分类**（benniechenbin）：100-200行/批，输出严格 JSON `{text,label,note}`
- **词级时间戳判别 A vs B**（bbc/react-transcript-editor）：同文本+时间递增=教学、时间重叠=水印

### C. 架构/工具参考
- **SubtitleEdit**（13.8k star，全球字幕组十几年验证）：A/B/C/D 四个机械清洗问题全有算法模板，C# 易译 Python

## 三、有必要重构的内容（含确认点）

### R1. 规则引擎从"布尔删"升级为"检测器分类 → 多动作决策器" ⚠️ 需确认

**冲突**：现状 `noise_substr/noise_regex` 是"命中即删整行"布尔动作。要支持 A 压缩保留/ E 保护/ D 合并，必须加动作类型。

**重构理由**：400 仓共识——问题不是"规则不够多"，而是缺 4 样：① 句子级粒度（sentencex）② 检测器分类 ③ 多动作决策（保/压缩/删/合并）④ 审计+门禁。

**融入建议**（融合 cleanlab + BufferFis + android-edittext-validator）：
```yaml
# cleaning_rules.yaml version 4
actions: {delete, compress, protect, merge}   # 由二元"删"升级为四动作
watermark: {min_count: 30, spatial_uniformity: true, patterns: [...], except_teaching: true}
compress_repeat: {min_count: 3, match: near, output: "{text}…[出现{count}次]", require_teaching: true}
protect_teaching: {ipa: "...", wordcard: "...", zh_translation: true, imperative: [...]}
garbled: {dict: wordfreq, no_vowel_ratio: 0.15, min_len: 8, exempt_from: [protect_teaching]}
line_merge: {trigger: "无终止标点+小写开头+时间<300ms", never_merge: [protect_teaching]}
```
工作量 ~150-250 行 schema + 引擎分发，零新依赖。

### R2. 处理粒度从"行"升"句"（sentencex 前置） ⚠️ 需确认

**冲突**：现在按行处理，拆行的台词永远匹配不上（D 根因），也导致重复检测失配。

**重构理由**：neurosnap/sentencex/syntok 三份一致：先句子归一化再判内容。

**融入建议**：`pip install sentencex`（轻量，52ms），Stage1 后加 `_normalize_sentences()` 前置层。**依赖仅 1 个纯 Python 库**。

### R3. 破坏性删除 → 审计 + 空输出回退 ⚠️ 需确认

**冲突**：现在删除不可逆，误删无法回滚。

**重构理由**：adrianmusante 三层保险（dry-run/自动备份/空输出回退）+ BufferFis 审计（edits+why）。

**融入建议**：`clean_batch.py` 加 `--dry-run`；删除规则执行后统计删除率，超 70% 整体回退原文（ffsubsync min_keep_ratio=0.3）。

### R4. 新增"教学保留率"质量门禁 ⚠️ 需确认

**冲突**：现有 14 项验收只测"规则生效"，不测"有没有误删教学"。

**重构理由**：balance-joe failure_count==0 / FilippoCrc golden set 回归——防规则越改越激进。

**融入建议**：建"教学保留基准集"（标 保/删/压缩），改规则后跑门禁；加"教学保留率"量化指标。

### R5. 必做无需确认：删 F1 高频删除块

`cleaning.py:303-304/336-337` 的 `high_freq` 全局计数删除逻辑必须删除，换成 R1 的 compress_repeat。

## 四、处理顺序（多仓库共识，关键）

```
原始行(带时间戳/帧号)
 → [E 教学白名单摘出 PROTECTED]        ← 最先, 保精华
 → [D 拆行合并 sentencex/mergeShortLines] ← 恢复语义
 → [C 乱码删 词典/熵]                  ← 删确定噪音
 → [B 水印删 时间戳判据/UI特征词]        ← 删固定界面词
 → [A 台词压缩 时域归并+[出现N次]]       ← 保教学强调
 → [LLM 兜底 歧义行裁决]
 → 还原 PROTECTED 行
 → 输出喂 Claude
```
**顺序不能反**：先保精华 → 再合并 → 删噪音 → 最后压缩高频。

## 六、结论

**400 仓调研确认**：A-E 问题都有成熟可移植的 GitHub 方案，核心是——
1. **A 台词**：删掉"全局计数≥3次删"（F1 元凶），换"时域相似度归并 + 压缩保留 [出现N次]"（YaoFANGUK + gnehs 三家合流）
2. **B 水印**：时间戳判据（间隔恒定=教学/近零=水印）或 UI 特征词 + 高频
3. **C 乱码**：教学白名单前置 + 词典命中率 + 字符熵四层漏斗，默认保守
4. **D 拆行**：三判据合并（上行无标点+下行小写+时间相邻），sentencex 升级
5. **E 教学**：教学词表/音标/单词卡/翻译结构保护，放最前

**架构层面**：规则引擎从"布尔删"升级为"检测器分类 → 多动作决策（保/压缩/删/合并）→ 审计 → 门禁"四层。

**5 个重构点里 4 个需确认**（R1-R4），1 个必做（R5 删 F1）。建议先阶段 1 纯规则修 bug，用真实 179 帧数据验证。
