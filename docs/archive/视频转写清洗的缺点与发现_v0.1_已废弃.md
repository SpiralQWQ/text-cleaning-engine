## 发现的缺点（4 个）

### 缺点 1：ASR 结构化丢失（🔴 最不合理）

**现象**：`英文测试.json` 有清晰结构——`text`(3445字) + `segments`(105段，含时间戳/置信度) + `sentences`(116句，含分句/时间戳)。清洗后**只保留 text 拼成一长段**，segments/sentences 结构全丢。

**影响**：对 Claude 生成笔记，分句/分段的文本比一长段**更好读、更准**（能对齐"这句在说什么"）；时间戳还有定位价值（回看视频某段）。

**期望**：清洗应**保留结构化输出**（逐句/逐段，或至少分句），不是拼成一段。

### 缺点 2：段落重复未去重

**现象**：asr 同一段对话（"Okay, everybody, listen up..."）在转写里重复了 **3 遍**（视频反复放这段），清洗没去重。

**影响**：Claude 可能重复整理；笔记冗余。

### 缺点 3：OCR 碎片 vs 教学短行难区分

**现象**：清洗后残留 143 行碎片里，**混着 OCR 乱码**（`dnrduork`/`Laundry`/`爱悦英烫`/`Dishuching`）和**有效教学知识点**（`Listen up.`/`大家听好了（用于多人）`/英文例句）。

**难点**：两者都是"单次无标点短行"，规则无法区分——删乱码会误删教学，留教学会带乱码。

### 缺点 4：ASR/OCR 词级错误（转写工具质量问题）

**现象**：
- ASR：`S tla r`(stellar) / `acc commodation s`(accommodations) / `D ed a great deal`(Dad got) / `T. He Duncans`(The) / `い`(日文残留)
- OCR：`dnrduork` / `Dishuching` / `Laundry`

**影响**：这些是 **FunASR/OCR 识别错误**，标点/规则清洗处理不了。

**期望**：换更好 ASR/OCR，或交给 Claude 生成笔记时理解纠正（Claude 能凭上下文推断正确词）。

## 可改进方向（待调研）

| 方向 | 说明 | 对应缺点 |
|------|------|---------|
| 结构化输出 | 清洗保留 segments/sentences（分句/时间戳） | #1 |
| 段落去重 | 文本级重复段合并 | #2 |
| 短行智能区分 | 区分 OCR 乱码 vs 教学短行（需 LLM/更复杂规则） | #3 |
| ASR 后处理 | 词级纠错/规范化（工具级，非清洗） | #4 |

## 结论

清洗工作流对"结构性噪音"（帧标记/标签/水印/标点）清得很干净、内容没删；但**结构化保留（#1）是当前最大的不合理**——json 转一长段丢结构，应优先改进。其余是转写质量 + 去重问题，需 GitHub 调研找方法。
