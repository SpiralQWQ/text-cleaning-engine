# 视频转写清洗 · 修复计划与建议

> **版本**: v0.1 · **状态**: 已废弃（被补丁重构计划_v1.0取代） · 归档于 2026-08-11
> **日期**: 2026-08-10 · **针对**: 4 个缺点（结构化丢失/段落重复/OCR碎片/词级错误）
> **依据**: GitHub 调研（faster-whisper/whisperX/stable-ts/AI4Bharat）

---

## 一、调研仓库技术栈/架构对比

| 仓库 | star | 技术栈 | 核心能力 | 架构 |
|------|------|--------|---------|------|
| **faster-whisper** | 24.8k | Python + CTranslate2 + PyAV(内嵌FFmpeg) | 快速 ASR（70x realtime），**输出 segments(时间戳+文本+置信度)** | CTranslate2 推理引擎加速 OpenAI Whisper 模型 |
| **whisperX** | 23.5k | Python + wav2vec2 + pyannote(说话人) | Whisper + **词级时间戳对齐** + **说话人分离** | ASR → 词级对齐(wav2vec2 forced alignment) → diarization |
| **stable-ts** | 2.3k | Python + Whisper | 稳定分句/时间戳/音频索引 | 改进 whisper 时间戳不准、词分组 |
| **AI4Bharat** | 8 | Python + pandas + indic-nlp | 转写清洗(去标点/字符规范化/字典去OOD) | 逐行规则清洗(训练数据预处理) |

## 二、技术方案对比（针对 4 个缺点）

| 缺点 | 当前(清洗工作流) | GitHub 可选方案 | 判断 |
|------|-----------------|----------------|------|
| **① 结构化丢失** | json→一长段 | faster-whisper/stable-ts **输出本身就是 segments 结构** | **转写源有结构，是我们清洗丢了** → 改进我们自己 |
| **④ 词级错误** | 标点规范化(已做) | faster-whisper 比 FunASR 更准；AI4Bharat 去标点 | 换 ASR 源 或 LLM 兜底 |
| **② 段落重复** | 未去重 | 无专门库；MinHash/SimHash 成熟算法 | 自研"相邻重复段合并" |
| **③ OCR碎片** | 规则到极限 | 无专门库 | LLM 理解兜底 |

## 三、修复计划（补丁方案）

### 补丁 A（🔴 高，清洗层）：结构化输出

**目标**：解决"json→一长段"——保留 segments/sentences 结构。

**实现**：清洗 `video_asr` 形态时，**不拼成一长段**，而是按 json 的 segments/sentences 逐句/逐段清洗输出：
- 输入：json（text/segments/sentences）
- 清洗：对每个 segment/sentence 的 text 做标点规范化 + 噪音清除
- 输出：**保留分句/分段的文本**（每句一行 / 每段一段，可选保留时间戳）

**改动位置**：`cleaner/cleaning.py` 的 `video_asr` 处理 + 输出格式
**价值**：Claude 分句读更准，时间戳可定位

### 补丁 B（🟡 中，清洗层）：相邻重复段合并

**目标**：解决"对话重复 3 遍"。

**实现**：清洗后做**相邻重复检测**——相邻段落文本相似度高(>90%) → 留一份。
**改动位置**：`cleaner/cleaning.py` 加"相邻去重"步骤（用 SequenceMatcher）
**价值**：去视频反复播放的冗余

### 补丁 C（🟡 中，转写源层，可选）：faster-whisper 替代 FunASR

**目标**：解决"词级错误"（转写源升级）。

**实现**：media-to-notes 的 ASR 环节换 faster-whisper（更准 + 输出 segments 结构）。
**改动位置**：`media-to-notes`（转写工具），不是清洗工作流
**价值**：源更准，下游清洗/笔记质量提升
**注意**：需 CUDA（CTranslate2），本机有 GPU（RTX 4060）

### 补丁 D（🟢 低，LLM 兜底）：词级错误 + OCR 碎片

**目标**：残余错误（S tla r/dnrduork）靠 Claude 理解。

**实现**：生成笔记时 Claude 凭上下文推断正确词、忽略 OCR 乱码。
**改动位置**：Claude 生成笔记的提示词（media-to-notes）
**价值**：无需代码，靠 LLM 能力

## 四、集成方式

```
media-to-notes 转写
  ├─ faster-whisper(补丁C) → json(segments 结构)
  └─ OCR+视觉 → visual.txt
      ↓
清洗工作流(补丁A/B)
  ├─ video_asr: 按 segments 结构化清洗 + 相邻去重 → 分句文本
  └─ video_ocr: 帧标记/水印/碎片清理 → GLM描述
      ↓
Claude 生成笔记(补丁D: 上下文纠错/忽略乱码)
```

## 五、优先级与步骤

| 步骤 | 补丁 | 工作量 | 依赖 |
|------|------|--------|------|
| **1** | **A 结构化输出** | 中 | 无（清洗层，现在能做） |
| **2** | **B 相邻去重** | 小 | 无 |
| 3 | C faster-whisper | 中 | media-to-notes 改造 + CUDA |
| 4 | D LLM 兜底 | 小 | 提示词 |

**建议**：先做 A（结构化输出）+ B（去重）——解决你最在意的"一长段不合理"和"重复"；C/D 是转写源/笔记层，可后续。

## 六、结论

GitHub 没有"一步到位"的库；但有明确的**技术路径**：
1. **清洗层**（我们能做）：补丁 A 结构化输出 + B 相邻去重——直接解决用户痛点
2. **转写源**（可选）：faster-whisper 升级（更准 + 有结构）
3. **LLM 兜底**：残余错误靠 Claude

核心洞察：**转写工具（whisper 系）输出本来就是结构化的**，我们的清洗应该"消费结构"而非"拼平"——这是本次修复最重要的方向。
