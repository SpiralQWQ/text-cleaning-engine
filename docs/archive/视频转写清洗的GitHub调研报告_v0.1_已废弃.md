## 一、缺点与对应 GitHub 方案

### 缺点 1：ASR 结构化丢失（json → 一长段）🔴

**发现**：whisper 系列转写工具**本身输出结构化**（segments 含时间戳/分句），是我们清洗时把 json 拼成一段丢结构。

| 工具 | star | 能力 | 对我们的意义 |
|------|------|------|------------|
| **faster-whisper** | 24.8k | 快速 whisper，输出 segments（时间戳+文本+置信度） | 转写源头就有结构 |
| **whisperX** | 23.5k | 词级时间戳 + 说话人分离 | 结构 + 说话人（多角色视频有用） |
| **stable-ts** | 2.3k | 稳定分句/时间戳（whisper 增强） | 分句更准 |

**方案**：**清洗应保留 json 的 segments/sentences 结构**（逐句/逐段输出，可选保留时间戳），不拼成一长段。这是**我们清洗输出方式的改进**，不是引入新库。

### 缺点 4：ASR 词级错误（S tla r/acc commodation）⚠️

**发现**：无专门高 star 的"转录词级纠错"库；但有转写清洗/规范化思路。

| 工具 | star | 能力 | 适用性 |
|------|------|------|--------|
| **AI4Bharat/speech-transcript-cleaning** | 8 | 去标点/字符规范化/字典去 OOD | 偏 ASR 训练数据清洗，对我们词级错误帮助有限 |

**方案**：
- 换更好 ASR（faster-whisper 比 FunASR 更准？需对比）
- 或 **LLM 纠错**：Claude 生成笔记时凭上下文推断正确词（最实际）
- 我们的标点规范化（`,,`/`..`）已做，词级错误靠 ASR 质量/LLM

### 缺点 2：段落重复未去重 🟡

**发现**：无专门"转录去重"库；MinHash/SimHash 是成熟算法（`datasketch` 等通用库），低 star 个人项目多是教学 demo。

**方案**：
- **简单版**：清洗加"文本级重复段合并"（相邻重复段 → 留一份）——视频反复放同一段，连续重复
- **通用版**：MinHash/SimHash 近似去重（数据多了用）

### 缺点 3：OCR 碎片 vs 教学短行难区分 🟡

**发现**：无专门库（OCR 后处理/口语规范化搜索为空）。

**方案**：
- 规则已到极限（两者都是单次无标点短行）
- **LLM 理解**：Claude 生成笔记时识别（教学短行保留、乱码忽略）——最实际
- 或更准的 OCR（当前 FunASR 附带的 OCR？）

## 二、推荐改进方案（优先级）

| 优先级 | 改进 | 对应 | 做法 |
|--------|------|------|------|
| **🔴 高** | **结构化输出** | 缺点1 | 清洗 json 保留 segments/sentences 结构（逐句/逐段输出，可选时间戳），不拼一长段 |
| 🟡 中 | 段落去重 | 缺点2 | 清洗加"相邻重复段合并"（视频反复播放的段落） |
| 🟡 中 | 词级质量 | 缺点4 | 对比 faster-whisper 是否更准；笔记阶段 Claude 纠错 |
| 🟢 低 | 短行区分 | 缺点3 | 靠 LLM 理解，规则不冒进 |

## 三、结论

1. **最关键**：whisper 系列工具**输出就是结构化的**——我们的清洗应该**保留结构**（逐句/逐段），这是清洗工作流的改进（`video_asr` 形态结构化输出），不是找外部库
2. **去重/纠错**：无专门高 star 库；用自研（相邻去重）+ LLM（纠错），或 better ASR（faster-whisper）
3. **OCR 碎片**：规则到极限，靠 LLM 理解

**一句话**：GitHub 上没有"一步到位"的视频转写清洗库；**最值得做的是我们自己改进"结构化输出"（保留 json 的 segments/sentences）**，其余（去重/纠错）用轻量自研 + LLM 兜底。
