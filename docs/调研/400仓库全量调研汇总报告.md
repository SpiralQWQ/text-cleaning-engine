## 三、反复出现的 6 大共性方案（多个 2 星仓库印证）

### 1. 【问题1 · 最高优先级】清洗应"消费结构"而非"拼平"
**核心洞察**：转写工具（whisper 系/FunASR）输出**本来就是结构化的**（segments/sentences 含时间戳）。是清洗层把 json 拼成一长段丢结构。

> 印证仓库：faster-whisper（源头 segments）、tenzir（结构化事件贯穿）、Umi-OCR（文块流分层）、transcriptionstream（句子重组）、OCRFlux（元素列表）、ropepenci/pdftools（双粒度输出）、VideoCaptioner（ASRDataSeg 片段保留）

**落地方案**：
- `clean_batch.py` 解析 ASR json 时，以 `segments[]/sentences[]` 为原子单位逐条清洗
- 清洗后按分句/分段输出（`\n` 拼接，可选保留时间戳）
- 规则层只做归一化/去噪，**不重排、不合并、不拼平**

### 2. 【问题2】段落去重 = 时间戳感知的相似度合并
**现状**：只有"整行精确重复 ≥3 次"删水印规则，视频反复播放同一段不处理。

**落地方案**（多仓库印证）：
- 相邻/近邻 segment 文本规范化后，`difflib.SequenceMatcher` 相似度 > 0.7-0.9 → 保留首现
- **时间戳辅助判据**：同文本 + 时间区间不重叠（Qwen3-ASR 报告的关键点）→ 防误删正常复读
- "短行高频 = 水印（删）" vs "长句周期重复 = 复读（折叠）"两种形态分开处理

### 3. 【问题4】词级纠错 = 三层叠加
**现状**：标点规范化已做，词级错误（`S tla r`/`acc commodation`）靠下游 LLM。

**落地方案**：
- **层1 规则**：词内空格重接正则（`\b([a-z])\s([a-z]{2,})\b`）+ 常见 OCR 混淆对表（l/1、O/0、rn/m）+ 领域术语表
- **层2 算法**：移植 VideoCaptioner 的 typoMap 纠错 + wordsegment 粘连切分（约 200 行纯 Python）
- **层3 可选 LLM**：按句切分后交给 Claude 修词级错误（明令禁止合并/拆分句子），失败保留原文

### 4. 【问题3】OCR 碎片 vs 教学短行 —— 规则到极限，两条辅助
**现状**：两者都是"单次无标点短行"，规则无法区分。

**落地方案**（多仓库印证）：
- **时间窗辅助**（Qwen3-ASR）：OCR 短行若其时间窗内有 ASR 语音覆盖 → 教学；无覆盖且高重复 → 碎片
- **几何特征辅助**（Umi-OCR）：若帧 OCR 保留 box 坐标，用行高/间距比区分（当前 OCR 无 box 则降级）
- **兜底**：靠下游 Claude 生成笔记时凭上下文识别（已确认）

### 5. 【工程】批量清洗增量续跑 + 中间产物可追踪
> 印证：ploomber、gnehs、VideoCaptioner（checkpoint 模式）

- clean_batch 记录每份产物的 `(输入hash, 清洗器版本, 规则hash)`，变更才重洗
- 每阶段输出可校验、可定位失败阶段

### 6. 【工程】校验/质检体系
> 印证：jiwer（WER 对齐可视化）、validators（装饰器注册）、WhisperJAV（modifications 审计台账）

- 用词级对齐做清洗前后对比报告（量化改进）
- 校验函数与规则名绑定，可追溯

## 六、结论

**400 仓库调研确认了核心洞察**：GitHub 上没有"一步到位"的视频转写清洗库，但存在**高度共识的技术路径**——

1. **最值得做（且现在能做）**：清洗层"结构化输出 + 相邻去重 + 词级纠错规则"——零新依赖，直接解决用户最痛的两点（一长段不合理 + 重复）
2. **转写源升级可选**：faster-whisper/Qwen3-ASR 源头降错（本机 4060 可跑）
3. **LLM 兜底**：残余错误靠 Claude 上下文纠正

> **实施需用户确认后才动手**。详细补丁建议见《高分仓库补丁建议汇总.md》（16 份仓库逐条方案）。
