## 一、可直接打补丁的

### rules/cleaning_rules.yaml 新增 5 区块（零依赖）
| 区块 | 内容 | 来源 |
|------|------|------|
| `protect_patterns` | 正则保护（连字符词/公式行），传 clean-text `exceptions=` | jfilter/clean-text |
| `lexicon` | 错误→正确词表，`\b` 整词匹配 | clean-text、jiwer、docetl |
| `dedup` | exact/similarity_threshold(0.85+)/min_len/ngram | ChenghaoMou、lovit |
| `line_classifier` | 碎片判别特征（行长度/bullet_point_ratio/ellipsis_line_ratio） | data-prep-kit、deequ |
| `acceptance` | 可接受偏差白名单 | datatest、neosync |
| `rep_removal` | length_threshold(20)/frequency_threshold(2) | data-prep-kit |

### cleaner/cleaning.py 3 处
1. `normalize_stage1()` 传 `exceptions`（v0.7 已支持）
2. 新增 `cleaner/dedup.py`（~100-150 行纯 stdlib）：5-gram → MinHash → Jaccard≥0.85 → 回原文 difflib 复检
3. 校验层升级"差异+白名单"两段式（datatest accepted() 模式）

### cli/clean_batch.py 2 处
1. ASR json 输入适配层（遍历 segments 保留 start/end，禁 join；时间戳间隙切段 >1.5s）
2. `_dedup_check` 升级：基于归一化文本判重 + 时间戳结合

## 二、可融入方法

"先保护→变换→恢复"（clean-text exceptions/antiplag）、去重"指纹初筛→候选→回原文复检"两步（ChenghaoMou/cleanlab）、判重前置归一化（数字归零+NFKC）、Blocking/分桶剪枝（dedupe/recordlinkage/dupeguru）、传递闭包合并（MihirAnam）、重复压缩而非删除（gnehs）、重复检测 5 指标（NeMo Curator Gopher）、"先打标后过滤"（data-prep-kit/deequ）、词级对齐 AlignmentChunk（jiwer）、相似词合并容错（dupeguru）、编辑距离容错公式（spaCy）、校验+重试（docetl）、小样本校准（docetl）、LLM-as-stage（NeMo Curator/docetl）

## 三、可作架构参考

声明式流水线（texthero/pyjanitor/ploomber）、先画像后清洗（DataCleaner/deequ）、先审计→脱敏→复核闭环（arx/neosync）、声明式 schema 校验（cerberus/schema）、JSON Schema 输出契约（pydantic）

## 四、我们项目没有的优点

结构感知处理、词级置信度信号、可接受偏差白名单、指纹+复检两步去重、相似词合并容错、传递闭包、LLM 纠错层、小样本校准、脱敏参数模型、checkpoint 断点续传

## 五、我们项目已有的缺点

拼长串再清洗（clean-text 报告明说）、规则校验硬编码 if、近似去重粒度粗（前300字>0.75）、行分类无特征集、词级纠错空白、无 LLM 可插拔层

## 六、该避免的错误

别用 texthero 默认管线（删标点毁分句）、别引 C++/Faiss/后缀数组全家桶、别引 AGPL、别引无 License、别引停更项目、别照抄 remove_two_char、别用 TF-IDF 稠密矩阵、别整文档丢弃、别为单一问题背模型、去重前必须先修问题1

## 七、可借鉴技术栈

`rapidfuzz`、`jellyfish`（damerau_levenshtein 换位距离）、`pydantic`（结构锁定）、规则文件自检（jsonschema 扩展）、`opencc`（繁简归一化）

## 八、冲突需重构

normalize_stage1 fix_unicode 一刀切（中英分叉）、clean_text str-in/str-out 签名、去重位置在清洗之后（移到段落级）、校验层硬编码、_RULES_SCHEMA 需扩展、YAML 只有删行动作

## 九、跨问题安全红线

1. **去重必须排在问题1修复之后**（拼平后去重粒度错误导致整段误删）
2. **词级错字会反向破坏 TF-IDF/语义去重**（问题4纠错应在去重之前执行）
