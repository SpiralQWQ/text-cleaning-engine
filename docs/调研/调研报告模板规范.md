# 调研报告模板规范（400 仓库统一）

> **用途**: 400 个仓库的每份调研报告**统一结构**，保证可比性
> **产出**: `docs/调研/报告/{仓库名}.md`（每仓库一份）

---

## 每份报告的固定结构（8 段）

### 1. 仓库基本信息
```markdown
> **仓库**: owner/name · **star**: N ⭐ · **语言**: XX · **协议**: XX
> **定位**: 一句话（它解决什么问题）
```

### 2. 功能详解（表格）
```markdown
| 能力 | 说明 | 我们是否需要 |
|------|------|------------|
| ... | ... | ✅/⚠️/❌ |
```
**列出核心能力**，逐条标注"我们是否需要"（针对我们的清洗/视频转写场景）。

### 3. 架构
```markdown
流程图或文字描述核心设计（输入→处理→输出）
```

### 4. 技术栈
```markdown
| 层 | 技术 |
|----|------|
| 核心 | ... |
| 依赖 | ... |
```

### 5. 难易程度（评分 ⭐1-5）
```markdown
| 维度 | 评分 | 说明 |
|------|------|------|
| 安装 | ⭐ | ... |
| 上手 | ⭐ | ... |
| 定制 | ⭐ | ... |
| 成本 | ⭐ | ... |
```

### 6. 与我们的融合度（对比我们的项目）
```markdown
**我们的项目**: 清洗工作流（网页/文本/视频转写→干净文本，cleaner/ 引擎 + rules/ 规则 + clean_batch 批量）

| 融合点 | 可行性 | 说明 |
|--------|--------|------|
| 视频转写清洗 | ⭐ | 能否解决我们的 ASR/OCR 问题 |
| 结构化输出 | ⭐ | 能否保留 json 的 segments/sentences |
| 词级纠错/去重 | ⭐ | 能否解决词级错误/重复 |
| 清洗工作流 | ⭐ | 能否作为我们 cleaner 的补丁/替代 |
```

### 7. 是否值得 + 原因（三档评分）
```markdown
**评分**: ⭐⭐⭐ 直接打补丁 / ⭐⭐ 借鉴思路 / ⭐ 不值得
**原因**: 具体说明（针对我们的场景）
```

### 8. 补丁建议（对我们项目的具体动作）
```markdown
**建议**: 怎么融入我们的清洗工作流（改哪、加什么、是否引入依赖）
```

---

## 输出要求（Workflow agent 遵循）

1. **每份报告 1 个 md 文件**，文件名 `{owner}_{name}.md`
2. **格式严格按上面 8 段**，不省略任何段
3. **融合度/值得度/补丁建议**是重点（结合我们的清洗工作流 + 视频转写 4 个缺点）
4. **内容真实**（基于仓库 README/描述，不编造）
5. 报告放在 `docs/调研/报告/` 目录

## 分类侧重点（不同方向报告侧重）

| 方向 | 侧重 |
|------|------|
| ASR/语音 | 转写质量/segments结构/能否替代 FunASR/词级纠错 |
| 字幕/视频文本 | 字幕提取/对齐/去重 |
| OCR | 识别精度/噪音/能否处理 OCR 碎片 |
| 清洗/质量 | 去重/校验/脱敏/能否补我们规则 |
| 文档解析 | PDF→MD/结构保留 |
| 管道/ETL | 编排/增量/并行（借鉴 clean_batch） |
| NLP/文本 | 分词/纠错/规范化 |
| 爬虫/采集 | 数据获取（辅助） |
| 数据源/存储 | 数据/向量（辅助） |
