# 知识库整合方案 — 40 篇知乎干净文本入 RAG

> **日期**: 2026-08-10 · **定位**: D1 方案(D1.1)，经审核后按此实施
> **版本**: v1.0 · **状态**: 常备参考 · 更新于 2026-08-11
> **目标**: 把清洗后的 40 篇知乎方法论文本加入现有简历知识库 RAG，
>          让 BossJobAI 检索时能命中"知乎答主的简历方法论"（区别于 GitHub 仓库的模板/代码）

---

## 一、现状盘点

| 项 | 现状 |
|----|------|
| RAG 工具 | `本地样本/build_rag.py`（全量重建，免 faiss，numpy + jsonl） |
| 语料源 | `repos/`（200 个 GitHub 简历仓库：文档全量 + 源码每仓抽样）+ `简历知识库_详细内容.md` |
| 切块 | 700 字符 / 100 重叠 |
| 向量 | BAAI/bge-m3，1024 维，GPU 加速 |
| 产出 | `本地样本/rag/`（index.npz + chunks.jsonl + meta.json），约 4 万块 |

## 二、目标与差异

**加入什么**：`知识库_clean/` 下 40 篇知乎方法论 txt（已清洗，保留率 52%，正文完整）。

**与现有语料的互补**：
| 语料 | 内容 | 价值 |
|------|------|------|
| GitHub 200 仓 | 简历模板/工具/代码/README | 成品模板、实现 |
| 知乎 40 篇（新增） | 简历方法论（STAR/量化/排版/HR视角） | 写作思路、经验总结 |

两类互补：模板提供"长什么样"，知乎提供"怎么写、为什么这么写"。

## 三、整合方案（改动点明确）

**改动 `本地样本/build_rag.py` 的 `collect_files()`**，新增一个语料源：

```python
# 新增: 知乎干净文本语料
ZHIHU_CLEAN = os.path.join(BASE, '..', '_crawl', '知识库_clean')
# collect_files() 末尾追加:
if os.path.isdir(ZHIHU_CLEAN):
    for root, dirs, names in os.walk(ZHIHU_CLEAN):
        for fn in names:
            if fn.endswith('.txt'):
                fp = os.path.join(root, fn)
                text = open(fp, encoding='utf-8', errors='ignore').read()
                rel = os.path.relpath(fp, ZHIHU_CLEAN)
                files.append({'source': f'知乎/{rel}', 'text': text})
```

- `source` 标记 `知乎/{词}/{文件名}.txt`，保证可溯源到具体知乎方法论文章
- 其余逻辑（切块/向量化/索引）完全复用，**零改动**

## 四、重建与验证

1. **重建**：`python 本地样本/build_rag.py`（全量重建，GPU，块数从 ~4 万增至 ~4 万+几百）
2. **验证**：`python 本地样本/test_rag.py`（现有 36 条查询）+ 新增知乎命中查询：
   - "如何量化简历成果" → 应命中知乎文本
   - "STAR法则怎么写" → 应命中知乎文本
3. **验收标准**：查询命中知乎 source 的块，证明方法论已入知识库

## 五、与 BossJobAI 对接

RAG 产出 `本地样本/rag/`（index.npz + chunks.jsonl）已是一体化检索库：
- 查询 → bge-m3 向量化 → 余弦相似度 → 返回 top-k 块（含 source 溯源）
- BossJobAI 简历功能调用此检索，即可同时获取"GitHub 模板 + 知乎方法论"

## 六、风险与成本

| 项 | 评估 |
|----|------|
| 改动范围 | 仅 `collect_files()` 加 ~10 行，零逻辑改动 |

## 七、结论

方案可行且低成本：build_rag.py 加一个语料源（~10 行）→ 全量重建 → 验证命中。D1.2 审核通过后按 D2 实施。
